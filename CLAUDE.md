# dc-deck — гид для Claude Code

Читай этот файл первым. Затем `PLAN.md` (текущая веха + стоп-гейт) и
`DECK-CONTRACT.md` (контракт данных) — **до** того как трогать данные, слоты или шаблоны.

## Что это

Веб-дек для еженедельной Дхармачакры (ДЧ). Заменяет ручную сборку Google Slides.
Дек **рендерится из данных**, а не правится вручную. Человек меняет данные, никогда — вёрстку.

## Главный принцип

**Дизайн — константа кода. Данные — переменная.**
Дек = `manifest ∪ selection ∪ theme`. Пустой слот → заглушка, не падение.

## Три слоя данных (где что живёт и почему)

| Слой | Где | Кто правит | Частота | Блокировки |
|---|---|---|---|---|
| `manifest.json` | файл, печётся на **Маке** (открытый интернет), пушится на VPS | я | еженедельно | Google/Airtable/Groq — только на Маке |
| `selection` | **Postgres на VPS**, через форму `/operator` | кто угодно, без VPN | в течение недели | нет исходящих внешних вызовов |
| `theme.json` | файл в репозитории | я, вручную | редко | нет |

VPS **сам наружу не ходит**. Он отдаёт статику дека и обслуживает форму+БД.
Всё блокируемое (LLM, Airtable, Google) — на стороне Мак-билда.

## Конвенции (обязательны)

- **Postgres 16:** при создании БД нужны `GRANT ON DATABASE` + `GRANT ON SCHEMA public` + `ALTER OWNER`. Одного GRANT ON DATABASE мало.
- **Caddy — единственный TLS/прокси.** Не поднимать nginx/Apache. Не трогать другие сайты на сервере при деплое.
- **Заглушки явные.** Где нет реальной интеграции (Telethon, Airtable без ключа, видео пусто, песня не найдена, сервер недоступен) — показывать явную заглушку «тест/демо» или «нет данных». Никаких фейково-рабочих поведений.
- **Одна точка LLM на весь пайплайн** — `build/extract_program.py`. Больше LLM нигде. Всё остальное детерминированно.
- **Оверрайд, не перезапись.** Ручные правки программы/новостей пишутся в `selection.overrides`, а не в `manifest`. Пересборка manifest их не затирает.
- **rsync — whitelist, не blacklist.** Пушим только явно перечисленные пути. После пуша — проверка, что не утекло лишнего.
- **Живые сайты не рушим** во время деплоя. Дек на своём поддомене, изолирован.

## Порядок слайдов (фиксированный)

`welcome → program → news → song×N → video → dada → final`

Слайд 1 (`welcome`) — приветствие выбирается **правилом** (утро/вечер по времени старта программы, порог 12:00 МСК), а не полем формы. См. `DECK-CONTRACT.md`.

## Карта репозитория

```
deck/      — reveal.js, статика. boot.js: fetch → merge → render. Один файл = один слайд.
server/    — FastAPI + Postgres на VPS. /api/*, /operator (форма). seed_songs.py.
build/     — Мак-сторона. extract_program.py (LLM), extract_progress.py (regex, raised), fetch_news.py (Airtable), fetch_telegram.py (Telethon: пост программы+финансов), build_manifest.py, add_song.py (ввод песни → songs_seed.json), push.sh.
data/      — manifest.json, схема, songs_seed.json, sample/.
infra/     — Caddyfile, systemd-юнит.
theme.json — цвета/шрифты/фоны.
```

## Как работать

1. Открой `PLAN.md` → найди активную веху (помечена `← ТЕКУЩАЯ`). Делай **только её**.
2. Перед правкой данных/слотов/шаблонов сверься с `DECK-CONTRACT.md`. Имена полей — оттуда.
3. Дойдя до стоп-гейта вехи — **остановись**, не продолжай на следующую. Жди подтверждения.
4. Модель: по умолчанию Sonnet. Если веха сложная — явно скажи «нужен Opus» перед началом.

## Критерий готовности скелета

Дек рендерится end-to-end на sample-каталоге из 2 песен. Форма пишет `selection`.
Оверрайды переживают пересборку manifest. Реальный сид песен подставляется позже.
